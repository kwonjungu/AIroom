# 감수 의견 조사서 B — 심사위원 태블릿 채점 화면(오른쪽으로 계속 밀어야 하는 불편)

- 대상: 위원 채점 화면(초대 링크로 여는 `/recruitment?id=…`, `/hub/s/<학교>/recruitment?id=…`), `public/recruitment/style.css`·`app.js`
- 관점: **심사위원이 태블릿(세로·가로)을 손에 들고 지원자를 한 명씩 채점한다**
- 작성: 2026-11-10 · 수정 담당 Claude · 감수 판정은 별도 감수 에이전트
- 원칙: 채점 규칙·점수 계산·저장 데이터 모양·PC 넓은 화면의 표 보기·휴대폰 카드 보기는 바꾸지 않는다. 태블릿 폭의 배치와 이동만 고친다.

## 2. 위원 관점 불편(감수 의견)
| 번호 | 불편 | 근거 |
|---|---|---|
| B-1 | 지원자 한 명을 채점하려면 표를 오른쪽으로 최대 2천 px 넘게 밀어야 한다 | 1절 측정, 계약제는 심사관점 목록이 한 줄에 6개 |
| B-2 | 그 지원자의 **합계와 메모 칸이 화면 밖 맨 오른쪽**이라 점수를 넣으며 합계를 확인할 수 없다 | `app.js` 채점표 열 순서: 지원자·참석·항목들·가점·합계·메모 |
| B-3 | 표 상자 안 스크롤(세로 높이 제한 + 가로 스크롤)과 페이지 스크롤이 겹쳐, 손가락으로 밀 때 어느 쪽이 움직일지 헷갈린다 | `.score-wrap{max-height:calc(100vh - 150px)}` + `.table-wrap{overflow-x:auto}` |
| B-4 | 안내 문구가 "표를 좌우로 밀어서 보세요"라고 불편을 그대로 요구한다 | `app.js` `.wide-only` 문구 |
| B-5 | "표 머리글에 평가 준거 함께 보기"를 켜면 열마다 174px 가 더 붙어 더 넘친다 | `.guide-check:checked~.table-wrap .th-guide{width:174px}` |
| B-6 | 카드로 바꾸면 세로로 길어지므로(지원자 최대 20명) **지원자 사이를 바로 오가는 길**과 **누가 아직 덜 채점됐는지** 보는 장치가 필요하다 | 개선 뒤 생길 새 불편을 미리 막음 |

## 3. 개선 계획
| 단계 | 내용 | 파일 |
|---|---|---|
| P1 | 태블릿 폭(641~1366px)과 손가락 기기(`pointer:coarse`, 641px 이상)에서 채점표를 **지원자별 카드**로 바꾼다. 카드 머리에 접수번호·이름·참석·**합계**, 그 아래 심사 항목을 화면 폭에 맞춰 1~3칸 격자로 배치(`auto-fill, minmax`), 메모는 맨 아래 전체 폭. 표 상자 안 스크롤을 없애 페이지 스크롤 하나로 만든다 | `style.css` |
| P2 | 카드 보기에서는 쓸모없는 "머리글에 평가 준거" 단추와 "좌우로 밀어서" 문구를 숨긴다(준거는 위쪽 평가 준거 상자에 그대로 있음) | `style.css` |
| P3 | 채점표 위에 **지원자 바로가기 줄**(접수번호 단추, 화면 위에 붙음)을 두고, 단추마다 채점 상태(빈칸 있음/다 채움/불참)를 표시한다. 누르면 그 지원자 카드로 이동 | `app.js`, `style.css` |
| P4 | PC 넓은 화면(1367px 이상, 마우스)의 표 보기와 휴대폰(640px 이하) 카드 보기는 그대로 둔다 | — |
| P5 | 시험: `tablet_e2e.py` 30가지 경우 넘침 0, 누름 칸 44px 이상, 실제 눌러서 채점·임시 저장, 바로가기 이동. 기존 `e2e.py` 27/27, `npm run test:recruitment` 유지. 크기별 화면 사진을 눈으로 확인 | `tests/recruitment/tablet_e2e.py` |

## 5. 수정 기록
### 1차 수정(2026-11-10)
- P1·P2 `style.css` 끝의 '태블릿 채점' 블록: `@media (min-width:641px) and (max-width:1366px), (min-width:641px) and (pointer:coarse)` 에서 채점표를 지원자별 카드 격자로(`grid-template-columns:repeat(auto-fill,minmax(260px,1fr))`). 카드 머리 = 접수번호·이름 / 참석 / 합계(20px), 메모는 전체 폭. 표 상자 안 스크롤 제거, 준거 머리글 단추·'좌우로 밀어서' 문구 숨김. 개수·체크 칸 44px.
- P3 `app.js`: 채점표 앞 `<nav class="cand-jump">`(접수번호 단추), `syncScoreTotals` 가 단추마다 상태(done/blank/absent, aria-label) 표시, `jump` 동작은 그 지원자 카드로 이동만(저장·다시 그리기 없음, 자판이 뜨지 않게 초점 안 줌). 줄은 화면 위에 붙고(sticky) 카드 보기에서만 보인다.
- P4: 휴대폰(640px 이하) 규칙과 PC 표 규칙은 손대지 않음. 바로가기 줄은 그 두 보기에서 `display:none`.
- 시험 `tests/recruitment/tablet_e2e.py`(40건): 5개 태블릿 크기 × 두 심사표 모든 전형(25가지)의 옆 넘침·누름 칸, 768 세로에서 눌러 채점·임시 저장 5건, 768 세로·1180 가로에서 바로가기 이동·상태 10건.
- 결과(수정 후): 옆 넘침 **0px**(수정 전 최대 2,128px), 44px 미만 누름 칸 0, `tablet_e2e.py` 40/40(두 번 연속), `e2e.py` 27/27(휴대폰 폭 포함), `npm run test:recruitment` 111 통과·1 건너뜀. 확인 주소 `http://127.0.0.1:3199/recruitment?id=…#invite=…`(하네스 서버).


### 2차 수정(2026-11-10, 1회차 감수 FAIL 반영)
- 결함(두 줄 바로가기 줄 밑에 카드 머리 가림): 고정값 `scroll-margin-top:84px` 를 없애고, `app.js` `jumpTo()` 가 **바로가기 줄의 실제 높이 + 화면 위에 붙은 띠 높이**(`stickyTop()`, 카피본 시연 바)만큼 비켜서 `scrollTo` 한다.
- 권고 1(카피본 시연 바): 바로가기 줄의 `top` 을 `var(--jump-top)`(시연 바 높이, `syncScoreTotals` 가 매번 설정)으로 해서 시연 바 밑에 깔리지 않게 함.
- 권고 2(지금 보는 지원자 표시): 스크롤할 때(rAF 한 번으로 묶음) 줄 바로 아래 카드의 단추에 `aria-current="true"` + 파란 테두리.
- 시험 `tablet_e2e.py` 강화: 지원자 **20명**(줄 두 줄, 115px), 모든 태블릿 크기·전형에서 가운데·끝 근처 지원자로 이동해 카드 머리가 줄 아래 40px 안에 보이는지와 현재 표시를 확인. 768·1180 에서는 시연 바를 흉내 낸 위 띠를 넣고 다시 확인.

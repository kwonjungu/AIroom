## 판정 방법
1. 조사서 1~5절을 읽고, `git diff` 로 실제 바뀐 코드를 전부 읽는다.
2. 판정 기준 항목마다 직접 확인(시험 실행, 코드 추적, 필요하면 Playwright 로 화면 확인)하고 근거를 적는다.
3. 기준 밖의 문제도 찾는다: 회귀, 보안 후퇴, 본질(설계·권한·도메인 규칙) 변경, 경계 상황 누락, 다른 화면(학교 공간 `/hub/s/<id>/recruitment`, 카피본 `/copy/recruitment`, 관리자 화면)에 미치는 영향.
4. 판정은 **PASS** 또는 **FAIL** 둘 중 하나. 사소한 의견은 '권고'로 따로 적되 PASS 를 막지 않는다. FAIL 은 고쳐야 할 결함이 하나라도 있을 때.

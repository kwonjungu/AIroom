# 검수·평가·출시 기준

이 문서는 앞으로 달성할 기준이다. 현재 제품이 통과했다고 주장하지 않는다. 조사 때 확인한 값은 `evidence/browser-audit.json`과 개편 전 PNG에 한정한다. 표시된 정량 기준은 초기 목표이며 파일럿 전에 기준 기기·네트워크·표본을 고정한다.

## 3. 모델 평가 corpus와 합격 기준

총 120과제: 받기/피하기/모으기/미로 4장르 × 5유형 × 6개 변형. 유형은 첫 생성, 시각·속도 변경, 규칙 추가, 모호한 한국어/오타, 기존 규칙을 유지하는 복합 수정. 학년별 문장 길이와 “느리게/조금/덜 어렵게” 같은 상대 표현을 포함한다.

80개 개발 세트와 40개 holdout을 분리한다. holdout 정답을 프롬프트 예시에 넣지 않는다. 각 모델 설정을 같은 seed와 예산으로 3회씩 평가하고 결과를 평균뿐 아니라 분자/분모로 보고한다. 미지원 요청 20개, 오류/취소/악성 입력 20개는 별도 강건성 세트다.

평가 정답은 AI가 자기 응답을 평가하는 문장만으로 결정하지 않는다. schema, 의미 invariant, 결정적 replay, 브라우저 smoke, 사람이 보는 의도 적합성을 합친다. “게임이 켜짐”과 “학생이 요청한 게임”을 구분한다.

| 지표 | 파일럿 출시 목표 | 측정 정의 |
|---|---|---|
| 첫 후보 실행 가능 | 90% 이상 | 수리 전 의미+런타임+조작 검사 통과 |
| 최종 실행 가능 | 97% 이상 | 최대 1회 수리 뒤 통과, 수리율 별도 |
| 수정 보존율 | 98% 이상 | 요청 밖 기존 invariant 유지 |
| 요청 충족률 | 90% 이상 | 정해둔 독립 의도 체크리스트 |
| 무검증 적용/데이터 유실 | 0건 | 자동·수동 검사 전체 |
| 템플릿 준비 시간 | p95 2초 목표 | 캐시된 템플릿 선택→조작 가능, 생성 시간 제외 |
| 단순 AI 수정 지연 | p50 4초 / p95 12초 목표 | 요청→검증된 후보, 큐 포함·별도 breakdown |
| 첫 게임 생성 지연 | p95 20초 목표 | 요청→검증된 후보, 에셋 대기 제외 |
| 전체 처리 상한 | 기본 40초 | 넘으면 기존 작품 유지·실패 상태 |

위 백분율은 작은 holdout의 오차가 크므로 반드시 `예: 116/120회`처럼 실제 건수와 반복 편차를 표시한다. 출시 후 실제 작업 수가 늘면 목표를 재확인한다. 평균 토큰·p95 토큰·실제 요금표 기준 작업당 비용·수리당 추가 비용을 함께 보고한다. 가격을 이 문서에 고정하지 않는다.

모델이 기준을 못 맞추면: 지원 장르/동작을 줄임 → 템플릿·계약 개선 → 최소 예시 개선 → 필요한 작업만 더 적합한 모델 → 다시 holdout. 낮은 품질 모델로 조용히 전환해 실패율을 숨기지 않는다. 모든 모델이 부적합하면 카드·템플릿 편집을 제공하고 생성 지원 범위를 명시한다.

## 4. 게임·화면 성능 예산

| 항목 | 초기 기준 |
|---|---|
| 셸 초기 전송 | 압축 JS+CSS 300KB 목표, Blockly·모드 엔진 지연 로드 |
| 첫 화면 필수 이미지 | 600KB 목표, 전체 작품 에셋 선다운로드 금지 |
| 필수 장르 한 게임 | 전체 에셋 2MB 목표, 미사용 에셋 해제 |
| 주 기기 실행 | 60fps 목표. 저사양 실기기 최소 30fps, 최악 대표 장면 60초 측정 |
| 프레임 처리 | 60fps 모드에서 처리시간 p95 16.7ms 목표, 실제 rAF 간격과 별도 보고 |
| 입력 반응 | p95 100ms 이하 목표, 터치 시작→가시 반응 |
| 반복 사용 | 모드 전환 100회 후 잔여 타이머/리스너 0, 힙 단조 증가 없음 |
| 페이지 UX | LCP 2.5초, INP 200ms, CLS 0.1 목표. 실제 측정 조건 함께 기록 |

첫 화면 바이트는 기존 전체 앱을 한 번에 로드하면 달성하기 어려우므로 학년·모드별 분할 로딩을 포함한다. 외부 CDN 차단에 대비해 필요한 블록 라이브러리·폰트를 버전 고정 배포하고 학교 네트워크에서 확인한다. 목표 미달 시 장식 효과를 줄이되 규칙을 바꾸지 않는다.

## 5. 실제 수업 파일럿

초기 관찰 표본 제안: 저학년 6명 이상, 3~4학년 6명 이상, 5~6학년 6명 이상. 연구 결과 일반화 표본이 아니라 사용성 결함 발견 목적이다. 별도로 한 학급 규모 동시 접속을 검사한다. 교사의 적절한 안내·학교 동의 절차 안에서 진행하고 학생 원문·영상은 기본 수집하지 않는다.

과제:

1. 저학년: 첫 카드 미션 진입 → 잘못된 순서를 바꾸기 → 도형 완성 → 한 번 되돌리기.
2. 3~4학년: 받기 게임 생성 → 직접 플레이 → 낙하 속도 변경 → 저장·다시 열기.
3. 5~6학년: 피하기에 목숨/성공 조건 추가 → 오류 힌트 이해 → 기존 규칙 보존 확인.
4. 공통: 네트워크가 끊겼을 때 현재 작품을 계속 사용하고 저장 상태 구분.

관찰: 처음 행동까지 시간, 잘못 누른 횟수, 도움 요청 위치, 다음 단계 이해 여부, AI 실패 후 복귀 여부, “내가 바꾼 것”을 말할 수 있는지. 재미는 사용시간만으로 판단하지 않고 자발적 수정·자기 작품 설명·수업 후 짧은 선호 응답으로 평가한다. 일일 접속 압박·실패 감점·과도한 보상으로 체류 시간을 늘리지 않는다.

파일럿 목표: 각 경로 과제 수행 80% 이상이 교사 직접 조작 없이 완료. 작은 표본이므로 실제 성공/전체 수를 같이 기록. 실패한 단계는 출시 전 수정하고 같은 과제로 재확인한다.

## 6. 릴리스 게이트와 롤백

- G0 기준: 현행 데이터 백업, 사용자 변경 보존, 실제 테스트 명령, v2 플래그.
- G1 사용성: UI/SH 필수 항목 및 실제 태블릿·크롬북 통과.
- G2 생성: RT/ST/AI 필수 항목, holdout 결과, 비용·지연 예산 통과.
- G3 운영: OP/AS 필수 항목, 30명 버스트, 큐 재시작 복구, 권한 검사.
- G4 파일럿: 학년별 과제 관찰·치명 결함 0·교사 운영 흐름 확인.

릴리스 차단: 타 학생 데이터 접근, 작품 소실, 검증 전 코드 적용, API 키 노출, 무제한 유료 호출, 주요 기기에서 실행/저장 불가, 화면 전체 멈춤, 의미 없는 정상 처리 표시. P2 장식·추가 장르는 이러한 문제보다 먼저 배포하지 않는다.

preview→선정 학급→확대 순서. 버전별 UI/엔진/프롬프트/계약 플래그를 기록한다. 치명 결함 1건이면 해당 경로를 즉시 제한하고 기존 정상 버전으로 복귀한다. 관측 최소 100작업에서 최종 실행 실패율 5% 초과 또는 p95 지연이 목표의 2배로 10분 지속되면 자동 경고·점진 확대 중단을 초기 규칙으로 둔다. 실제 표본 규모와 수업 시간에 맞춰 보정한다.

롤백 리허설: v2로 작품 저장 → v2 생성 기능 끄기 → 기존 작품 읽기/내보내기 → 이전 정상 엔진으로 재생 가능한 버전 선택. 스키마 손상·파괴적 마이그레이션으로 되돌릴 수 없게 만들지 않는다.

## 7. 구현자가 제공할 검사 명령

다음은 새로 만들어야 할 진입점이며 현재 존재하는 명령이라고 가정하지 않는다.

```text
npm run test:vibe:unit       파서·채점·상태·엔진
npm run test:vibe:contracts  JSON Schema·라우트·어댑터·버전
npm run test:vibe:e2e        기기별 핵심 흐름·실패 경로
npm run test:vibe:a11y       자동 접근성 + 수동 확인 목록
npm run eval:vibe:mock       provider 오류·수리·시간·비용 상한
npm run eval:vibe:live       승인된 키/예산으로 실제 고정 corpus
npm run test:vibe:load       preview의 가짜 학생 30명
```

`eval:vibe:live`는 기본 CI에서 자동 유료 실행하지 않는다. 일반 PR은 mock·계약·엔진·E2E, 모델/프롬프트/문법 변경에는 예산 있는 실제 평가를 추가한다. 결과물에는 빌드 SHA·환경·명령·실행 시각·성공/실패/미실행·스크린샷/trace·비용을 붙인다.

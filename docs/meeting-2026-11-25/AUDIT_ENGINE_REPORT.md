**확인된 보호와 남은 검증 범위**

- `/copy`는 서버 차단과 라우터 첫 검사로 이중 방어한다(`server.js:230–232,277`, `routes.js:49`). pt는 서버 난수·해시·mid·exp를 검사하고, 코드 승격은 원자 시도 장부·PBKDF2를 사용한다. 주관 코드 6자리·녹음 기본 허용은 `DECISION_ANSWERS.md`와 다르지만 `DESIGN.md:62,380`에서 의도적으로 변경된 사항이므로 구현 누락으로 세지 않았다. 한도 검사 뒤 거절된 요청도 회의 전체 시도 수에는 남는다(`routes.js:249–253`).
- 비공개 원표는 Redis에만 있고, 일반 조회·reveal·md에서 개인 선택을 공개하는 경로는 발견하지 못했다(`routes.js:717–778`, `keys.js:30–38`). 진행의 cid·epoch·baseRev 확인과 forceSeq 증가는 트랜잭션 안에 있다(`routes.js:330–340`). 다만 실제 Firestore 경합 검증은 14번이 남는다.
- 서비스 계정 REST는 클라이언트 규칙과 다른 인증 경로다(`gcp.js:55,63`). 클라이언트 Firestore 쓰기 금지 자체가 서버 쓰기를 막는 불일치는 아니다. 실제 IAM·`kwon` 규칙 배포·Storage CORS·토큰 교환 뒤 SDK 접근은 이번에 검증하지 않았다. 앞선 보고서의 실제 키 확인과 Rules API 16/16 기록도 이번 재실행 결과로 간주하지 않았다.
- 기존 앱은 ba에 쭘 외 경로, cp에 `copy/`만 허용한다. 두 SPA 모두 NONE 설정과 업로드 인증 호출이 있다. GitHub Pages의 상대 API는 Vercel로 변환되며 `X-Auth-Token` CORS도 허용된다(`index.html:2393–2395`, `public/index.html:2524–2526`, `server.js:202–212`). 정적 경로상 새 토큰 API만 미러에서 빠지지는 않는다. 실제 교차 출처 로그인·업로드는 **확인 필요**. 쭘 미러는 설계상 안내만 제공하는 범위다.
- 이미 발급된 다운로드 URL의 token은 잠금 규칙만으로 회수되지 않는다(`storage.rules:12`). 카피본에 그런 실서비스 URL이 전달되면 읽기는 가능하다. `defaults-copy` 검색에서 해당 URL은 발견하지 못했지만 운영 Redis의 카피 데이터는 읽지 않았으므로 **확인 필요**. cp만으로 실서비스 Storage SDK 경로를 직접 읽고 쓰는 허용문은 없다.
- 녹음은 raw **3MiB** 제한이라 지시서의 Vercel **4.5MB** 요청 한도 안에 있다(`routes.js:748`). 최종 함수 번들·최악 시간·콜드 스타트는 미측정이다. 최상위 JSON parser 10MB가 먼저 실행돼 쭘의 1MB parser가 별도 상한을 강제하지 못하는 점도 통합 시험에 넣어야 한다(`server.js:225`, `routes.js:53`).
- 정상 변환 경로의 HWP `free`, PDF `destroy`, 이미지 `close`, 새 PPTX `destroy`는 있다. 오류 경로·중도 취소·대형 입력의 최대 메모리는 별개다. 현재 PPTX 전체 변환·글꼴 없는 기기·Safari/Firefox 결과는 이 감사에서 직접 확인하지 않았다. CDN 대체 경로로 언급된 `zzoom-vendor`도 현재 읽기 금지라 그대로는 사용할 수 없다(`storage.rules:58–59`).

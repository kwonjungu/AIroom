# 아스트라 판단 요청 (사용자가 판단을 아스트라에게 위임함)

맥락: `AUDIT_REPORT.md`(당신이 쓴 감사), `DECISIONS.md`(사용자 결정). 설계 v2 는 다음 구조로 바꾼다:
**브라우저는 Firestore·Storage 를 읽기만 하고(맞춤 토큰, claim `mid`·`role`·`until`), 모든 쓰기는 서버 API 가 firebase-admin 으로 한다.** 참가 자격(참가 토큰)은 서버가 탭마다 발급하고 Redis 에 `{cid, name, role, exp, grantVer}` 로 보관해 쓰기마다 확인한다. 원표(ballots)는 Firestore 에 두지 않고 Redis 에만 두며 서버가 집계 문서만 Firestore 에 쓴다.

아래 각 질문에 **하나를 골라 한 줄 이유**와 함께 답하라. 파일은 `docs/meeting-2026-11-25/DECISION_ANSWERS.md` 하나만 만든다. 다른 파일은 고치지 않는다.

1. 구형 `.ppt`: (a) `.pptx` 자동 변환 + `.ppt` 는 「PPTX·PDF로 저장해 올려 주세요」 안내 (b) 외부 변환 서비스 연동
2. 비공개 투표에서 주관자가 개인별 표를 볼 수 있나: (a) 아무도 못 봄(서버만 앎) (b) 주관자는 봄
3. 공개 투표는: (a) 결과 보이기 때 이름별 선택까지 공개 (b) 공개 투표도 숫자만
4. 읽기 권한 회수 최대 지연(주관 코드 변경·회의 삭제 시 이미 받은 Firebase 토큰의 읽기): (a) ID 토큰 수명 1시간까지 허용, 쓰기는 즉시 차단 (b) 즉시 회수 필요 → (default) DB 접근 제어 문서 추가
5. 진행권: (a) 진행자 한 명(presenterId+epoch), 다른 주관자는 「진행 넘겨받기」 (b) 여러 명 동시 진행
6. 준비만 하고 시작하지 않은 회의·고아 업로드: (a) 모두 같은 규칙(첫 열쇠 발급 또는 생성 + 10일 뒤 삭제), 고아 업로드는 24시간 뒤 정리 (b) 다른 규칙
7. 관리자 host 경로: (a) 백암이 admin 세션이면 주관 코드 없이 host 자격 (b) 관리자도 주관 코드 입력
8. 탭 단위 참가 자격(sessionStorage) vs 기기 단위(localStorage): 투표 1표 기준과 다중 탭 문제를 고려해 (a) 탭 단위 + 한계 명시 (b) 기기 단위 + 탭 하나만 활성
9. 주관 코드 최소 강도: (a) 숫자 6자리 이상 (b) 영문+숫자 8자 이상
10. 녹음 Groq Whisper 전송: 학교 회의 음성이 외부 서비스로 나감. (a) 주관자 고지 확인 + 안내 후 사용 (b) 기본 꺼짐, 관리자가 회의별로 허용해야 켜짐

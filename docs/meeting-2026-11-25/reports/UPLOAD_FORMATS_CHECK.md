## 확인 방법

1. 「안건 추가」 창에서 제목과 파일을 넣고 「안건 추가하기」를 누르면 변환, 미리보기(「모두 N쪽이에요」), 「이대로 올리기」, 안건 목록의 쪽 수 표시까지 가는지 봄. 변환 시간은 추가하기를 누른 때부터 미리보기가 뜰 때까지, 올리기 시간은 「이대로 올리기」부터 목록에 쪽 수가 보일 때까지.
2. 쪽 수: 목록의 「N쪽」이 미리보기 쪽 수와 같고, PDF·PPTX·이미지는 만든 쪽 수와 같음.
3. 「발표하기」(확인 창에서 「예」) 뒤 발표자 화면에서 `.zv-ov-empty`(「아직 자료가 없는 안건이에요」)와 `.zv-ov-error` 가 없고, 쪽 그림(캔버스나 blob 이미지)이 실제로 칠해졌는지 스크립트로 확인. 쪽 번호가 「1 / N」인 것도 확인.
4. 둘째 기기: 다른 접속 문맥(다른 기기 ID, 다른 토큰)으로 같은 회의에 들어가 같은 확인을 함.
5. 한글 깨짐: 아래 스크린샷을 직접 봄. HWP 22쪽 첫 쪽의 굵은 제목·표, HWPX 달력의 표 글자, PPTX 「한글 시험 슬라이드 1」, PDF 「한글 시험 PDF 1쪽」, PNG 「한글 시험 그림 PNG」 모두 정상으로 보임.

「아직 자료가 없는 안건이에요」가 남는 일은 18건 모두(9형식 x 2폭) 없었다. 발표 화면에 쪽 그림이 곧바로 뜸.

## 실패와 원인

- 형식 실패는 없다.
- 390 폭을 처음 돌릴 때 준비 단계(/zzoom 첫 접속)가 `Page.goto` 25초 시간 초과로 멈췄다(학교망 연결 끊김으로 보임, 요청이 ERR_ABORTED). 회의를 만들기 전이라 만든 회의는 없었다. 390 폭만 다시 돌려 9개 형식 모두 통과했다. 네트워크 오류로 형식 하나가 실패해 다시 시도한 경우는 없었다.
- 페이지 오류 수집에 Firestore 수신 채널(`Listen/channel`)의 `net::ERR_ABORTED` 가 폭마다 30건 남짓 찍혔다. 이 채널은 연결을 새로 맺을 때 브라우저가 이전 요청을 끊으며 남기는 신호이고, 시험 동작에는 영향이 없었다(자바스크립트 `pageerror` 는 0건, 4xx·5xx 응답도 없음).

## 참고(시험 도구의 한계)

- 스크립트의 `<형식>_host`, `<형식>_second`(번호가 앞선 파일) 스크린샷은 모두 주관자 화면이다(그림 확인 함수가 화면 인자를 넘기지 않음). 진짜 둘째 기기 화면은 번호가 뒤인 `<형식>_second.png`(예: pc1280_15_HWP_second.png) 이다. 그림이 보였는지는 스크립트 판정이 둘째 기기 화면에 대해서도 따로 했고, 둘째 기기 스크린샷을 눈으로도 확인했다.
- 「발표 화면 그림」 판정은 캔버스 픽셀이나 blob 이미지로 했으므로 형식별 시각 검수는 대표 화면(HWP, HWPX 허가원, HWPX 달력, PPTX, PDF, PNG)만 눈으로 봤다. 나머지(JPG, GIF, WEBP 등)는 판정만 통과.
- 시험 HWPX 서식 그림에는 서식에 들어 있던 이름·날짜가 그대로 보이므로, 스크린샷을 저장소에 올리지 않는다.

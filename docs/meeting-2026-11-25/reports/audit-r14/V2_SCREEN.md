## 문제

### L1(낮음) 0번 발표 중 「다음 ›」 단추가 꺼져 있을 수 있는데 띠는 「다음 ›」을 누르라고 한다
- 파일:줄: viewer.js:1051 `btnNext.disabled = !stepPage(...)`(손 화면 S.aid·S.page 기준), viewer.js:449 `step`(0번이면 지금 쪽으로 가는 새 길), viewer.js:939 띠 문구.
- 재현(r14b.py, `S11_single_agenda_1p_today_1280.png`): 안건이 하나(1쪽)뿐일 때 0번 발표 → 「다음 ›」 `disabled=true`. 띠는 「「다음 ›」이나 안건의 「발표하기」를 누르면 모두 그 자료로 넘어가요」. 오른쪽 화살표 키는 step 의 새 길을 타서 /live 를 보낸다(1번). 안건이 4쪽이고 발표자가 0번 전에 4쪽을 보고 있었어도 같다(뒤 안건에 자료가 없으면 꺼짐).
- 고칠 방향: paintPager 에서 `todayMine() && S.aid && !noFile(curA())` 이면 「다음 ›」을 켠다(step 과 같은 조건). todayMine 이 바뀌는 때(live·meeting 받을 때) paintPager 를 다시 부른다.

### L2(낮음) 0번 「다음 ›」은 「1쪽」이 아니라 발표자가 마지막으로 보던 쪽으로 간다
- viewer.js:449 `userGo(S.aid, S.page)`. FIXES 는 「깔린 자료의 지금 쪽(1쪽)부터」라고 적었다.
- 재현(r14.py S6, `S6_today_after_p3_1280.png`): 발표자가 1번 3쪽을 보다가 0번 발표 → 「다음 ›」 → `/live {aid:1번, page:3, force:true}`. 아래 막대도 「3 / 4」라 발표자 눈에는 맞지만, 모두는 1·2쪽을 건너뛴다. 0번 발표 중 「‹ 이전」(또는 왼쪽 화살표)은 3쪽에서 2쪽으로 모두를 보낸다.
- 결정(쪽 넘기기는 모두 같이) 안이라 기록만. 1쪽부터가 의도라면 `userGo(S.aid, 1)`.

### L3(낮음) 0번 발표자가 패널을 손으로 다시 연 채 「다음 ›」을 누르면 내 패널은 그대로 덮여 있고 문구가 「나만 그 자료를 봐요」로 바뀐다
- 파일:줄: agenda.js:20(`open` 이면 늘 full), app.js:385(yieldToPresenter 는 남만), agenda.js:183(발표자가 0번이 아니면 보는 사람 문구).
- 재현(r14.py S9, `S9_presenter_open_next_1280.png`): 0번 발표 → 「자료 화면 보기」 → 띠 「오늘의 안건 보기」 → 「다음 ›」. 모두는 1번 1쪽으로 넘어가고 내 띠는 「내가 발표 중이에요」인데, 내 가운데는 패널이 그대로 덮고 있다. 패널 안내는 「안건 이름을 누르면 나만 그 자료를 봐요」인데 발표자가 이름을 누르면 cmd:nav 로 모두 넘어간다(이 문구는 보통 발표자에게도 ab8da41 전부터 같음).
- 패널을 손대지 않은 0번 발표자는 mini 로 잘 접힌다(S2). 고칠 방향(선택): 내가 0번을 떠나는 /live 를 보낼 때 agenda 에 `cmd:yield` 같은 접기 신호를 보내고, 발표자에게는 「안건 이름을 누르면 모두 그 자료로 넘어가요」 문구를 쓴다.

### L4(낮음, 확인 못 함) 0번을 떠난 뒤 회의 스냅숏이 오기 전에 또 보내는 /live 도 force 가 붙는다
- viewer.js:591 `force = P.force || (!!S.live && !S.live.aid)`. S.live 는 회의 스냅숏으로만 바뀌므로, 첫 /live 응답 뒤 스냅숏이 늦으면 그 사이 확대·이동 /live 도 force 가 되어 forceSeq 가 여러 번 오른다. 보는 사람 쪽에서는 그때마다 yieldToPresenter(창 닫기·서랍 닫기)가 다시 돈다.
- 가짜 API 는 스냅숏이 응답보다 먼저 와서 재현되지 않았다(S2: 두 번 눌러도 force 한 번). 운영 순서는 확인 못 함. 고칠 방향: 0번을 떠나는 force 를 epoch 당 한 번만(예: 보낸 epoch 를 기억) 싣는다.

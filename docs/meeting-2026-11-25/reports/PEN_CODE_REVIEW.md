# 쭘 판서 코드 검토 (읽기 전용, 2026-11-26)

대상: public/zzoom/draw.js, draw.css, viewer.js(캔버스·손짓), zzoom.css, api.js, lib/zzoom/routes.js(strokes).
실제 기기에서 돌려 본 것은 아니고 코드만 읽었다. 확실도: [확실] 코드만으로 재현 경로가 보임, [추정] 조건이 맞아야 함.

먼저 확인한 정상 항목: 캔버스 CSS 크기(inset 0, 100%)와 backing 크기(stage × dpr)가 같은 값으로 맞춰지고(viewer.js:260-266), draw.js localXY는 temp.getBoundingClientRect 기준이라 스크롤·offset·DPR 좌표 어긋남은 없다. 지우개 hitStroke도 같은 vp(CSS px)로 계산해 좌표계가 맞다. 무대 touch-action: none(zzoom.css:102), pointercancel 처리, 측면 패널(<768px는 fixed 서랍)로 인한 폭 변화는 ResizeObserver로 다시 그려진다.

## 심각도 순 발견

### 1. [확실] 한 사람이 한 쪽에 300선까지, 지워도 몫이 돌아오지 않음 — 주관자도 예외 없음
- lib/zzoom/routes.js:28 (personPageStrokes: 300), 913-914, keys.js:55-58 ("지워도 돌려주지 않음"), 삭제는 routes.js:958에서 who=''로 사람 몫 미반환.
- 시나리오: 교사가 한 쪽에 형광펜·밑줄·글씨를 쓰다 지우고 다시 쓰기를 반복하면 301번째 획부터 409 stroke_limit_person. 클라이언트는 그 묶음(최대 20획)을 통째로 remove하고 토스트만 띄움(draw.js:434-436) → 화면에서 획이 사라짐. 글씨 한 자가 여러 획이라 300은 수업 한 쪽에서 쉽게 닿는다. 지우개로 정리한 획도 센다.
- 최소 수정: 삭제 때도 사람 몫을 돌려주거나(scRelease에 who 전달), 주관자는 사람당 상한 면제, 상한을 1000 안팎으로. 클라이언트는 이 오류에서 묶음 전체가 아니라 실패 획만 버리고 "이 쪽에 쓸 수 있는 선을 다 썼어요" 안내.

### 2. [확실] 획 도중 화면이 움직이면 획이 엉뚱한 자리에 찍힘
- draw.js:533 drawing.vp를 시작 시점으로 고정, draw.js:511 addPoint가 현재 화면 좌표(sx,sy)를 옛 vp로 변환, draw.js:298 임시 선도 옛 vp로 그림.
- 시나리오: 따라가기(follow) 중인 참석자가 쓰는 동안 진행자가 쪽을 밀거나 확대하면, 또는 마우스 휠로 확대하면 viewer의 view가 바뀌는데 획은 옛 변환으로 계산돼 놓이는 위치가 손끝과 달라진다. 획이 끝나면 ink 층이 새 vp로 그려져 선이 튀어 보인다. 두 손가락 핀치는 gesture로 취소되지만 이 경우는 취소되지 않는다.
- 최소 수정: store 'viewport' 구독에서 drawing이 있고 scale/ox/oy가 달라졌으면 cancelDrawing()하거나, addPoint에서 매번 현재 vp를 쓰되 이전 점도 같은 비율 좌표라 그대로 두면 된다(비율 좌표이므로 현재 vp로 변환하는 편이 맞다: toPage(vp,...)).

### 3. [확실] 펜 굵기가 쪽 너비 비율이라 휴대폰(390px)에서 너무 가늘다
- draw.js:11 pen.w=0.004, draw.js:59 size=w×쪽너비(쪽 화면 너비 기준). 쪽이 390px로 맞춰지면 약 1.6px, thinning 0.5와 mouse 속도 시뮬레이션으로 느리게 쓰면 더 가늘어짐. 형광펜 0.018은 약 7px.
- 시나리오: 폰에서 판서하면 "선이 거의 안 보인다/흐릿하다"로 느낌. 확대하면 선도 같이 굵어져 글씨 크기와 비율은 맞지만, 맞춤 상태의 가독성이 나쁨.
- 최소 수정: 화면 기준 최소 굵기를 둔다(렌더 시 size=max(w×pageW, 2.5/vp.scale)처럼 확대율 반영). 또는 pen.w를 0.006 이상, thinning 0.3으로.

### 4. [확실] 서버가 거절한 429·실패에서 선이 사라지거나 중복될 수 있음
- (a) 지우기 요청 실패 시 되살림: draw.js:472-476 404가 아니면 hidden에서 빼고 토스트. 429(rate_limited)·네트워크 끊김에도 되살려서, 방금 지운 선이 다시 나타난다. 재시도 없음. 지우기는 260ms 간격(draw.js:31)이라 초당 3.8회이고, 같은 참가 자격의 'all' 버킷(초당 8, routes.js:158,192)을 하트비트·live 등과 나눠 쓰므로 진행자는 닿을 수 있다.
- (b) 응답이 유실된 저장 재시도 중복: 서버는 저장 성공 뒤 응답이 끊기면 클라이언트가 같은 획을 다시 보내(draw.js:430-433) 같은 선이 두 번 저장된다. 멱등 키가 없다(routes.js:886-941). 형광펜은 두 겹이라 진해짐.
- 최소 수정: (a) 429·status 0·5xx면 delQueue 앞에 다시 넣고 백오프. (b) 획마다 클라이언트 id(lid)를 body에 넣고 서버가 같은 id를 무시.

### 5. [확실] 구독이 한 번 끊기면 다시 붙지 않아 남의 선이 멈춤
- api.js:531-544 live()는 오류 시 conn만 off로 하고 재구독이 없다. onSnapshot은 오류가 나면 그 리스너가 영구히 끝난다. api.js에는 subscribePageStrokes가 없고(draw.js:179-189 폴백으로 subscribeStrokes+subscribePageEpoch), 둘 다 같은 live를 쓴다.
- 시나리오: 토큰 갱신 순간의 permission-denied나 일시 오류 뒤 그 쪽의 남의 선이 갱신되지 않음("새로고침해야 보인다"). 쪽을 넘겼다 돌아오면(PAGE_LRU=1이라 재구독) 복구되므로 간헐적으로만 보임.
- 최소 수정: live()에서 err 시 몇 초 뒤 make를 다시 호출(지수 백오프). draw.js 쪽 변경은 없음.

### 6. [확실] epoch를 모를 때 그린 획은 구독이 안 오면 영원히 안 보내지고 실패 표시도 없음
- draw.js:533(epochKnown 아니면 epoch null), 397(epoch null이면 건너뜀), 379-386(epoch 구독 콜백에서만 정해짐).
- 시나리오: Firebase 로그인·구독이 늦거나 막힌 기기에서 쓴 선은 화면에는 보이지만 서버에 안 가고 "보내지 못했어요" 표시도 없다. 다른 사람에게는 안 보이고 새로고침하면 사라짐.
- 최소 수정: epoch null인 채 3~5초가 지나면 status 'failed'로 바꿔 「다시 보내기」를 띄우거나, 서버에서 GET으로 epoch를 받아 채운다(API 호출 하나).

### 7. [추정] 도구 막대가 폰에서 쪽 하단을 가리고 색 단추가 화면 밖
- draw.css:16 막대는 무대 오른쪽 아래 고정, 폭 max-content(max = 가운데 폭−24), draw.css:6 overflow-x: auto. 펜 켠 상태 단추들 합이 약 440px라 390px에서 가로로 밀어야 색·지우개가 보인다. 막대는 stage 밖 형제 요소(index.html:69)라 막대 영역에서는 판서 입력이 막힌다(높이 약 64px).
- 시나리오: 세로 쪽(A4 PDF)이 폭 맞춤일 때 쪽 맨 아래 64px는 막대에 가려 쓸 수 없고, 색 고르기를 모르는 교사는 "색이 안 바뀐다"고 느낀다.
- 최소 수정: <768px에서 라벨을 숨기고(아이콘만) 도구 단추 폭을 줄여 한 줄에 맞추기, 또는 막대를 두 줄(위: 모드·도구, 아래: 색)로 접기. 막대를 무대 안 맨 아래 가운데 얹는 대신 stage 아래 줄에 따로 둬서 쪽을 가리지 않게 하는 방법도 있음.

### 8. [추정] 손바닥(penSeen)이 한 번 켜지면 손가락이 평생 막히고, 뷰어는 손바닥 접촉으로 핀치를 시작함
- draw.js:518-519 penSeen은 한 번 true가 되면 되돌리지 않는다. 같은 기기에서 스타일러스로 한 번 쓴 뒤 손가락으로 쓰면 아무 반응이 없고(펜 모드 한 손가락은 뷰어도 팬을 안 함, viewer.js:521-535) 오류 안내도 없다.
- viewer.js:527-531: 펜 모드에서 터치 2개가 닿으면 penSeen과 상관없이 'gesture'를 내 그리던 펜 획을 취소하고 핀치를 시작한다. 손바닥+손가락이 스타일러스 쓰는 중에 닿으면 획이 사라지고 확대가 바뀐다.
- 최소 수정: penSeen에 시간 제한(마지막 펜 입력 후 5~10초, 또는 펜 hover/down이 없으면 해제). viewer.js는 pen 입력이 눌려 있는 동안(gesture 이벤트 직전) 터치 2개 핀치를 무시.

### 9. [확실, 경미] 한 획에 21조각이면 서버가 한 묶음 20개 한도로 거절
- draw.js:28 MAX_PARTS=21, draw.js:399 묶음 20 한도지만 한 획이 21조각이면(점 약 3만 개) 21개를 보내 routes.js:891 400. 현실에서는 거의 안 닿음. MAX_PARTS를 20으로.

### 10. [경미] 그 밖에
- draw.js:563 pointercancel이면 그린 획 전체를 버린다. Android에서 시스템이 중간에 취소하면 길게 쓴 획이 통째로 사라짐. 점이 충분하면(예: 10점 이상) 저장하도록.
- draw.js:117-118 quantize가 쪽 밖 좌표를 0~1로 잘라서 쪽 바깥에서 시작한 획은 쪽 가장자리에 붙은 직선이 된다. 쪽 밖에서 시작하면 무시하는 편이 낫다.
- draw.js:273-291 paintInk는 팬·핀치 매 프레임 전체 선(최대 2,000)을 다시 채운다. Path2D 캐시(draw.js:77)로 외곽선 계산은 피하지만 저사양 폰에서 확대·이동이 끊길 수 있음. 개선하려면 확대 중에는 ink 층을 CSS transform으로 미리보기하고 끝나면 한 번만 다시 그리기.
- draw.js:298 임시 선은 last:false, 확정 선은 last:true라 손을 뗄 때 끝부분이 미세하게 바뀐다(눈에 띄지 않는 수준).
- SEND_GAP 1.05초(draw.js:30)라 다른 사람 화면에는 획이 쓴 뒤 1~2초 늦게 나타난다. 서버 한도가 초당 3번(routes.js:50)이라 0.4초까지 줄여도 된다.

## 사용자가 말한 "판서가 잘 안 된다"와 가장 가까운 후보
1. 1번(300선 한도, 지워도 안 돌려줌) — 수업 중 길게 쓰면 갑자기 안 써짐.
2. 3번(폰에서 선이 너무 가늘다)·7번(막대가 가리고 색이 안 보임).
3. 2번(따라가기·휠 중 선 위치 어긋남), 5·6번(남의 선이 안 보임·안 보내짐).
먼저 사용자에게 "어느 기기에서, 쓰다가 갑자기 안 됐는지/선이 가늘었는지/남에게 안 보였는지"를 물어 위 후보를 좁히는 것이 좋다.

## 2. 한 일 (CONTRACTS 대로)
- **좌표**: `viewport = {aid,page,pageKey,pageW,pageH,scale,ox,oy,dpr,stageW,stageH}`, 쪽 비율 (x,y) → 화면 `ox + x*pageW*scale`. 세 canvas 를 `#zz-stage` 크기 × dpr(최대 3)로 맞춘다. 크기가 바뀌면 viewport 를 꼭 다시 낸다(3팀이 다시 그리게). `pageW/H` 는 agenda `sizes`(`[w,h]`·`{w,h}` 둘 다), 화이트보드 1600×1000.
- **view**: `{cx,cy,z}`, z 1~6, 기기마다 clamp(쪽이 화면보다 작으면 가운데). 
- **손짓**: 보기 모드는 한 손가락·마우스 끌기 이동, 두 손가락 확대, 휠(ctrl+휠은 터치패드 오므리기) 확대, 두 번 톡 확대·맞춤, 맞춤 상태에서 옆으로 밀면 쪽 넘김. 펜 모드는 touch 두 개 이상일 때만 받고 시작 때 `gesture:'multi'`, 마우스 가운데 단추 끌기 이동. stopPropagation·펜 모드 포인터 캡처를 하지 않는다.
- **따라가기**: 기본 따라감. 직접 넘기거나 확대하면 `follow:'free'` + 띠 「진행자 화면으로 돌아가기 (안건N M쪽)」. live 가 없을 때(시작 전) 혼자 넘겨도 자유 보기로 바꾸지 않는다. forceSeq 는 처음 본 값을 기준으로 삼아 옛 force 를 재생하지 않는다.
- **진행자**: `meeting.presenter.cid === role.cid`(또는 `role.presenter`)면 내 이동을 300ms 묶어 `sendLive(mid,{aid,page,view,force?})`. 한 번에 하나만 보내고 그동안 바뀐 것은 뒤이어 한 번. 내 메아리는 무시. `stale_rev` 면 서버 최신으로 맞춤(최신이 내가 보낸 것과 같으면 다시 보냄), `not_presenter` 면 보내기를 멈추고 참석자처럼 따라감, 연결 오류는 3번까지 다시. `cmd:force` 는 바로 force 로 보냄. 진행권을 얻거나 잃으면 지금 live 화면에서 시작.
- **그림**: 지금 쪽과 다음 쪽(안건 경계 넘음, 화이트보드 제외)만 받고 나머지는 `releaseImages(keep)`. 요청 번호로 늦게 온 결과는 버림. 썸네일은 지금 안건만, 보일 때 받음(IntersectionObserver). 실패하면 「쪽 그림을 불러오지 못했어요」+「다시 불러오기」.
- **화이트보드**: board.js `paintBoardBackground` 를 늦게 import, 없으면 흰 바탕.
- **안건 목록**: 번호·제목·쪽 수, 진행 중 안건에 「진행」, 썸네일에 진행 쪽 빨간 점, 「원본 받기」(`originalBlob`). 768px 미만은 쪽 막대 「안건」 단추로 `#zz-agenda[data-open]` 덮개.
- **쪽 막대**: 이전·n/m·다음·쪽 맞춤·배율. 다른 팀 칸(`#zz-board-actions`, `#zz-quick-hand`)은 건드리지 않고 맨 앞에 내 칸만 넣는다. 좁으면 container query 로 맞춤·배율을 숨기고, 더 좁으면 겹치지 않고 옆으로 밀린다.
- 자판: ←→·PageUp/Down 쪽, 0 맞춤, +/- 확대(입력칸·모달 안에서는 안 함). `store.page` 는 쪽이 바뀌면 바로, 확대·이동만이면 250ms 멈춘 뒤 낸다.

## 4. 요청 (통합 담당)
1. **도구 막대가 따라가기 띠를 가림**: `#zz-toolbar` 가 `#zz-center` 위쪽 가운데(top 12px)에 떠서 자유 보기 때 「진행자 화면으로 돌아가기」 단추를 덮는다(`real_edge_1280.png`, `real_chromium_820.png`). 도구 막대를 `#zz-stage` 기준으로 내리거나(예: `#zz-follow-bar` 를 막대 밖 흐름에 두고 toolbar top 을 띠 높이만큼), 띠가 있을 때 아래로 내려 주세요.
2. **820px(갤럭시탭 세로)에서 무대가 240px**: 안건 240 + 옆칸 340 이 고정이라 가운데가 240px 만 남는다. 쪽 막대의 「다음」이 옆으로 밀려 안 보이고 문서도 아주 작다. 1024px 미만에서는 옆칸을 처음에 닫아 두거나(서랍), 안건 칸을 덮개로 돌리는 등 배치 조정이 필요하다.
3. **api.js live 되감기 방지**: `sendLive` 성공 응답으로 store `live` 를 rev N+1 로 넣은 뒤 Firestore 스냅숏이 옛 rev 를 늦게 주면 store 가 되돌아가 다음 baseRev 가 옛 값이 된다. 같은 epoch 에서 rev 가 더 작은 live 는 store 에 넣지 않게 해 주세요(viewer 는 409 뒤 내가 보낸 화면이면 다시 보내는 것으로 버팀).
4. app.js 의 `body.side-closed` 기본값: 좁은 화면에서 옆칸 서랍이 열린 채면 쪽 막대를 덮는다(시험에서는 닫고 봄). 처음에 닫혀 있는지 확인 부탁.

## 5. 정한 것·남은 일
- 진행권을 넘겨받으면 내 화면이 아니라 지금 live 화면에서 시작한다(모두가 갑자기 옮겨지지 않게). 모두를 내 화면으로 옮기려면 「모두 내 화면으로」.
- 썸네일은 그림이 없으면 번호만 보인다. 화이트보드 썸네일은 그리지 않는다(흰 칸+번호).

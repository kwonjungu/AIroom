## 문제

### M1(보통) 0번 발표자가 안건 「발표하기」→「예」를 누른 뒤 띠가 「내가 오늘의 안건을 보여 주는 중이에요」에 머문다
- 파일:줄: viewer.js:548-553 `onLive`(발표자면 `presenterIncoming`·`markAgenda` 뒤 바로 return, `paintBar` 없음), agenda.js:280-283(R12 L2 고침: `cmd:nav` 뒤 `close()`가 먼저 `ui:wait` mini 를 내 띠를 그 순간의 옛 live 로 그림), app.js:384-389(회의 문서를 store 에 넣은 **뒤** `acceptLive`).
- 재현(가짜 API, 1280·390, d1.py·d2.py): 0번 발표하기→예, 1번 줄 발표하기→예. `sendLive {aid:'aaaaaaa1', page:1}` 가 나가고 모두는 1번 자료로 넘어가는데, 내 띠는 1.5초 뒤에도 `data-state="today"`, 「내가 오늘의 안건을 보여 주는 중이에요」, 단추 「발표 마치기」「오늘의 안건 보기」(`A1_stuck_1280.png`). 상관없는 회의 문서 변경 하나(참석자 수)가 오면 그제야 「내가 발표 중이에요」로 바뀐다(A2).
- 가짜 API 는 회의 스냅숏이 `sendLive` 응답보다 먼저 온다. 운영에서도 Firestore 스냅숏이 HTTP 응답보다 먼저 오면 같은 순서라 다음 회의 문서 변경까지 틀린 띠가 남는다. 응답이 먼저 오면 스냅숏 때 고쳐진다. 실제 순서는 확인 못 함.
- R12 화면 감사 때(present 를 다시 부르던 길)는 띠가 바로 바뀌었다. R12 L2 고침으로 생긴 되돌아감이다. 시험(agenda_e2e)은 이 길을 다루지 않아 152·74 모두 통과한다.
- 고칠 방향: `onLive` 발표자 길에서도 `paintBar()`(띠 서명 barSig 로 같은 모양이면 그리지 않음) 를 부른다. agenda_e2e 에 「0번 발표 → 1번 발표하기 → 예 → 띠 presenting」 단계를 더한다.

### M2(보통) 0번에서 안건으로 넘어갈 때 force 가 없어, 패널을 손으로 연 참석자는 패널이 자료를 덮은 채 남는다
- 파일:줄: agenda.js:281(이미 발표자 길은 `cmd:nav`), viewer.js:1090-1094·437-438(`userChanged`→`queueLive()` force 없음), app.js:385(남의 창 접기는 forceSeq 증가나 발표자 변경 때만), agenda.js:156(다시 펼치기만 forceSeq·aid 없음일 때), agenda.js:20(`open` 이면 늘 full).
- 재현(d3.py, 1280·390): 다른 분이 0번 발표 → 참석자가 왼쪽 쪽 목록 「0 오늘의 안건」을 누름(`cmd:agenda-open`, S.open=true) → 발표자가 1번으로 넘어감(forceSeq 그대로, 이미 발표자 길이 보내는 값과 같음). 참석자 띠는 「모두의 화면을 따라가는 중이에요 … 지금 1번 안건 1쪽이에요」인데 가운데는 「오늘의 안건」 패널이 그대로 덮고 있다(`G_left0_then_move_1280.png`). 패널을 건드리지 않은 사람은 mini 로 접혀 문제없다(대조).
- R12 전에는 `present()`가 forceSeq 를 올려 `yieldToPresenter`→`cmd:yield`로 접혔다. 「다음 ›」·화살표로 0번을 떠날 때(결정된 동작)도 force 가 없어 같다.
- 고칠 방향: 발표자가 0번(live.aid 없음)을 떠나는 첫 live 에 force 를 싣는다. 예: viewer.js `flushLive` 에서 `if (!S.live?.aid) body.force = true`. 이러면 이름·발표하기·다음·화살표 모두 같은 길로 남의 창이 접힌다(서버 forceSeq+1). 또는 agenda.js:281 뒤 `store.emit('cmd:force')`(이 길만 고침).

### L1(낮음) 0번 발표 중에도 아래 막대가 「1 / 4」이고 「다음 ›」은 1번 **2쪽**으로 간다
- viewer.js:448-451 `step`(발표자 손 화면 S.aid·S.page 에서 한 쪽), 스크린샷 `1280_3_me_presenting_today.png`(왼쪽 쪽 목록도 1번과 1쪽 그림이 현재로 강조).
- 재현(d2.py B): 0번 발표 중 「다음 ›」 → `sendLive {aid:'aaaaaaa1', page:2}`. 모두가 1쪽을 건너뛰고 2쪽부터 본다. 「다음을 누르면 모두 넘어간다」는 결정된 동작이고, 어느 쪽으로 가는지만 어색하다.
- 고칠 방향(선택): `todayMine()` 일 때 「다음 ›」은 지금 안건 1쪽(또는 첫 자료 1쪽)으로, 쪽 표시는 「0번」처럼.

### L2(낮음) 0번 발표 중 왼쪽 쪽 목록의 안건 이름을 누르면 확인 창 없이 모두 넘어간다
- viewer.js:804(`userGo`)→437-438. 재현(d2.py C): `sendLive {aid:'aaaaaaa1', page:1}`, 확인 창 0개. 패널 이름 누르기(agenda.js:263)는 확인 창을 거친다.
- 왼쪽은 「쪽 목록」(쪽 넘기기)이라 결정된 「쪽 넘기기는 모두 같이」에 든다고 볼 수 있어 기록만 한다. 패널 이름과 같게 하려면 `todayMine()` 일 때 `cmd:present` 로 돌린다.

### 그대로 둔 것(R12 결정)
- R12 L1(칩 때문에 0번 단추 밀림), L2(발표 가져오기 알림 문구), L3(보는 사람 큰 발표 단추 숨김)은 그대로이며 새로 문제 삼지 않는다.
- 390 에서 「모두가 오늘의 안건을 봐요.」 알림이 목록 2번 줄을 3.5초 가린다. 알림 위치는 공용이라 기록만.

## 흐름별 확인(문제 없음)
- rowToday(agenda.js:205-217): 회의 중이고 내가 0번 발표자가 아닐 때만 발표하기, 고치기·지우기 없음. 이름은 단추가 아니라 글자(누를 수 없음).
- 「안건이름 (발표하기)」(agenda.js:236·252, agenda.css `.za-line`): 넓은 화면은 이름 옆, 390은 이름 아래 줄. 단언과 그림으로 확인.
- goTo(agenda.js:263): 0번 발표 중 이름 누르기는 askPresent 확인 창. 확인 창 첫 초점은 「아니오」.
- askPresent 이미 발표자 길(agenda.js:280-284): present 를 다시 부르지 않음(`present` 호출 1번뿐, 429 없음). 화면 이동은 됨. 띠만 M1.
- 안내 문구: 패널(0번 발표자) 「안건 이름이나 「발표하기」를 누르면 확인한 뒤 모두 그 자료로 넘어가요」, 띠 「「다음 ›」이나 안건의 「발표하기」를 누르면 모두 그 자료로 넘어가요」. 실제 동작과 맞다.
- 다시 펼치기(agenda.js:153-157, 457-461): 남이 0번 발표하면 「자료 화면 보기」로 닫아 둔 사람도 펼침. 내가 안건 발표 중에 남이 0번을 가져가도 펼침(d4.py). 발표 마치기 뒤에도 펼침.
- viewer.js 띠: today·today-watch 순서 맞음, 패널이 펼쳐져 있으면 「오늘의 안건 보기」 숨김, 주관자는 today-watch 에서 「발표 마치기」 테두리 단추. 남이 0번에서 1번으로 넘어가면 보는 사람(주관자 포함) 띠가 follow 로 바뀜(d2.py E2).
- 왼쪽 0번(viewer.js:795-801): 누르면 서랍을 닫고 패널을 엶, 칩은 todayOn 일 때만.
- 큰 발표 단추(viewer.js:486): 0번 발표 중 숨김.
- app.js yieldToPresenter 조건(385): 0번 발표에도 남의 창을 접고, cmd:yield 에서 live.aid 가 없으면 패널을 펼친다. 발표 마치기(pc null)는 yield 없음.
- 콘솔·페이지 오류: 모든 재현에서 0.

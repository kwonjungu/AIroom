## 정한 것
- 쪽 지우기는 CONTRACTS 8절대로 3팀(draw.js), 화이트보드 띄우기는 3팀(board.js, `#zz-hostbar-board`). DESIGN_TEAMS 의 D5 줄과 다르지만 CONTRACTS 를 따랐다.
- 녹음 조각 번호 n 은 받은 기록의 가장 큰 n 과 이 탭이 쓴 번호(sessionStorage)보다 크게 잡는다(서버가 같은 n 을 덮어쓰므로).
- 녹음 고지 확인은 탭마다 회의마다 한 번(sessionStorage).
- 「모두 내 화면으로」는 2팀에 `cmd:force` 만 보낸다. 실패 안내는 2팀 몫.
- 안건 지우기는 겹 모달을 피하려고 같은 단추를 4초 안에 한 번 더 누르게 했다(「정말 지우기」).
- 업로드는 한 번에 파일 하나.

## 요청
- 통합(app·zzoom.css): `#zz-hostbar` 는 높이 64px 한 줄 고정이라 2팀·3팀 단추까지 들어가면 820px 에서 빠듯하다. 지금은 5팀 단추를 줄여 맞췄다. 넘칠 때 가로 스크롤(`overflow-x:auto`)을 막대에 주면 안전하다.
- 서버(S): 회의를 끝내면(`ended`) `transcribe` 가 409 라 마지막 1분 조각이 버려진다. 끝낸 뒤 1~2분은 받아 주거나, 화면이 끝내기 전에 조각을 먼저 보내게 할지 정해 주면 맞추겠다. 지금은 실패 표시만 남는다.
- 서버(S)·통합: `setState('recording', true)` 를 두 주관자가 각각 누르면 둘 다 녹음해 n 이 겹칠 수 있다. 누가 녹음 중인지(`recordingCid`)를 회의 문서에 두면 「다른 기기에서 녹음 중」을 정확히 보이고 막을 수 있다.
- 감사 08(PNG 대체 출력): 지금 `uploadAgenda` 가 WebP 가 아니면 `webp_unsupported` 를 던지고, 화면은 「엣지나 크롬 최신판에서 올려 주세요」로 바꿔 보인다. api 가 PNG 를 받게 바뀌면 화면은 고칠 것이 없다.

# 외부 감사 지시 (라운드 N) — 아스트라 수준

너는 이 코드를 처음 보는 독립 감사자다. 만든 사람의 설명을 믿지 말고 코드와 시험으로만 판단한다.
**쓰는 파일은 `docs/meeting-2026-11-25/reports/AUDIT_R<N>.md` 하나뿐**(N 은 부른 쪽이 알려 준다). 코드는 고치지 않는다. 커밋·푸시·배포·Firebase/Vercel 조작·실제 서비스 요청 금지. 한/글·PowerPoint 종료 금지.

## 기준
- 이전 감사 `AUDIT_ENGINE_REPORT.md`(아스트라, 지적 01~15)와 수정 보고 `reports/FIX_ENGINE.md`(및 이후 `reports/FIX_R*.md`).
- 설계 `DESIGN.md`·`DECISIONS.md`, 범위는 `AUDIT_ENGINE_BRIEF.md` 의 1~7 전부(보안, 창고 잠금, 정확성, Vercel 제약, 변환, 시험의 빈틈, 다음 단계 전 필수).
- 저장소 `CLAUDE.md` 함정(두 SPA, /copy 격리, vercel rewrite 금지).

## 꼼꼼함의 기준 (아스트라가 한 만큼)
1. **지적 01~15 를 하나씩 재검증**: 수정 보고를 믿지 말고 해당 코드를 줄 단위로 읽어 실제로 막혔는지 확인한다. 막혔다고 주장하는 시험이 정말 그 실패 경우를 재현하는지(시험을 수정 전 코드에 돌리면 실패했을지)도 본다.
2. **새 문제 찾기**: 이번 수정이 만든 회귀, 수정이 닿지 않은 비슷한 경로(같은 패턴의 다른 라우트), 동시 요청·중간 실패·재시도·만료 경계.
3. **직접 실행**: `npm run test:zzoom`, `npm test` 를 돌려 숫자를 그대로 적는다. 의심 가는 경로는 node 로 작은 재현 스크립트를 짜서(가짜 fb·Redis 사용, `tests/zzoom/fakes/`) 실제로 실패시키고, 명령과 출력 요지를 적는다. 재현 스크립트는 저장소 밖 임시 폴더에.
4. **규칙**: `firestore.rules`·`storage.rules` 를 서버가 실제로 쓰는 경로·claim 과 한 줄씩 맞춘다.
5. **두 SPA**: `ensureStorageAuth` 와 업로드·삭제 경로가 두 파일에서 같은지 diff 로 확인.
6. 추측은 「확인 필요」로 표시하고 근거를 적는다. 줄 번호 필수.

## 보고서 형식
- 맨 위 한 줄 판정: **PASS**(치명·중요 0건) 또는 **FAIL**.
- 표 1: 지적 01~15 재검증 — 번호·판정(해결/부분/미해결)·근거(파일:줄, 시험 이름).
- 표 2: 새 지적 — 번호·심각도(치명/중요/사소)·파일:줄·문제·실패 시나리오(입력 → 잘못된 결과)·고칠 방향.
- 실행한 명령과 결과 숫자.
- 한국어, 짧게.

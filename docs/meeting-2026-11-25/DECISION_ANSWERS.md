# 설계 v2 결정 답변

1. **(a) `.pptx` 자동 변환, 구형 `.ppt`는 「PPTX·PDF로 저장해 올려 주세요」 안내.** 이유: 외부 변환 서비스에 학교 문서를 추가로 보내지 않으면서 구형 파일의 이용 경로를 제공할 수 있다.
2. **(a) 비공개 투표의 개인별 표는 주관자·관리자도 볼 수 없고 서버만 처리.** 이유: 비공개라는 약속을 지키려면 화면·조회 API·내보내기 모두에서 개인별 선택을 노출하지 않아야 한다.
3. **(a) 공개 투표는 「결과 보이기」 때 이름별 선택까지 공개.** 이유: 투표 전에 이름 공개를 고지하면 공개·비공개의 의미가 분명해지며, 이름별 결과는 공개 조건을 검사하는 서버 API로만 제공해 원표의 Redis 보관 원칙을 유지할 수 있다.
4. **(b) 읽기도 즉시 회수하도록 `(default)` DB에 접근 제어 문서 추가.** 이유: 주관 코드 변경·회의 삭제 후에도 새 읽기를 허용하지 않도록 Firestore·Storage가 현재 권한을 검사해야 하며, 이미 내려받은 자료는 회수 대상에서 제외한다.
5. **(a) 진행자는 한 명(`presenterId`+`epoch`), 다른 주관자는 「진행 넘겨받기」 사용.** 이유: 인계 시 epoch를 올리고 이전 진행자의 요청을 거절하면 동시 조작과 늦게 도착한 명령으로 화면이 되돌아가는 일을 막을 수 있다.
6. **(a) 미시작 회의도 첫 열쇠 발급 시각(미발급이면 생성 시각)+10일 뒤 삭제, 고아 업로드는 24시간 뒤 정리.** 이유: 기존 보관 결정을 일관되게 적용하고 시작되지 않은 회의와 실패한 업로드가 무기한 남는 것을 막는다.
7. **(a) 유효한 백암이 admin 세션이면 주관 코드 없이 host 자격 발급.** 이유: 이미 부여된 관리자 권한과 입장 경로를 일치시키되, 서버가 실제 관리자 세션을 검증하고 `/copy`의 시연 세션은 제외해야 한다.
8. **(a) 탭 단위 참가 자격(`sessionStorage`) 유지 + 한계 명시.** 이유: 탭별 회의·역할을 격리할 수 있으며, 「참가 자격당 1표이고 새 탭·재발급으로 중복 참여가 가능하므로 1인 1표를 보장하지 않음」을 안내해야 한다.
9. **(b) 주관 코드는 영문과 숫자를 함께 포함한 8자 이상.** 이유: 주관 권한 탈취를 어렵게 하려면 코드 강도를 높이고 회의·참가 자격·IP별 서버 시도 제한을 함께 적용해야 한다.
10. **(b) 녹음은 기본 꺼짐, 관리자가 회의별로 허용해야 활성화.** 이유: 학교 회의 음성의 외부 전송을 명시적으로 통제하고, 허용 후에도 기존의 주관자 고지 확인·참석자 녹음 표시·학생 개인정보 발언 금지 안내를 유지한다.
